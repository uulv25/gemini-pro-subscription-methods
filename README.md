## 为什么 Gemini 订阅需要提交 Cookie？

这是 BeWild 这类代开通流程中最需要认真看的一步。

BeWild 的 Gemini 教程要求用户使用 Cookie-Editor，从已经登录 Google 账号的 `myaccount.google.com` 页面导出 Cookie JSON，再粘贴到订阅流程中。平台解释这是为了识别并操作用户自己的 Google 账号。

Cookie 不是普通的验证码。它可能代表当前浏览器中的登录状态，因此应当按以下原则处理：

- 只在官方流程明确要求时操作；
- 确认浏览器登录的是准备升级的 Google 账号；
- 不要把 Cookie 发给个人客服、群聊或陌生人；
- 不要把 Cookie 保存到公共电脑或云笔记；
- 操作完成后及时退出 Google 账号；
- 如果页面要求提交密码、短信验证码或恢复码，应先停止并确认用途；
- 开通后检查 Google 账号的安全活动和登录设备。

BeWild 教程也提醒，Cookie JSON 属于账号凭证，不应外发，并要求在同一浏览器中完成 Google 登录、插件操作和提交。

这一步是第三方订阅与官方自助订阅最大的区别。官方订阅一般只需要在 Google Payments 中选择付款方式，而 BeWild 的流程需要平台代替用户完成账号内的升级操作。能否接受这种方式，取决于你对便利性和账号凭证风险的取舍。
